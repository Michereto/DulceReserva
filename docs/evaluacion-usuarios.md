# Evaluación de usuarios - DulceReserva

Este documento recoge el procedimiento y las plantillas que se utilizarán para evaluar la facilidad de uso de DulceReserva.

La evaluación permitirá comprobar si las funciones principales son comprensibles y útiles para el personal de tienda y obrador.

Las pruebas con usuarios todavía no se han realizado. Este documento prepara su ejecución para una fase posterior.

## 1. Objetivo

Comprobar que los usuarios pueden utilizar las funciones principales de DulceReserva sin dificultades importantes.

Se observará especialmente la facilidad para registrar encargos, buscar pedidos, consultar las previsiones de producción y comprender los estados de los encargos.

## 2. Participantes

Se intentará contar con dos o tres personas que representen los perfiles principales:

- **Personal de tienda:** registro, búsqueda, modificación y entrega de encargos.
- **Personal de obrador:** consulta de encargos, previsiones de producción y cambio de estado a preparado.

Si no es posible contar con trabajadores de ambos perfiles, podrán participar compañeros o familiares, explicándoles previamente las tareas que deben representar.

Para proteger su privacidad, se identificarán mediante códigos como U01, U02 y U03, sin registrar nombres ni datos personales innecesarios.

## 3. Momento de la evaluación

La evaluación está prevista para abril de 2027, cuando exista una versión funcional de DulceReserva.

Se realizará durante las tareas de integración, pruebas y revisión de la interfaz previstas en la planificación de la Fase 3.

## 4. Tareas de evaluación

### Perfil de tienda

1. Registrar un encargo con los datos del cliente, producto, cantidad, fecha y hora de recogida.
2. Buscar un encargo utilizando el nombre del cliente o la fecha.
3. Modificar un encargo existente.
4. Marcar un encargo como recogido.

### Perfil de obrador

1. Consultar los encargos previstos para una fecha.
2. Filtrar los encargos por hora y producto.
3. Consultar las cantidades totales que deben prepararse.
4. Marcar un encargo como preparado.

Durante las pruebas se observará si cada participante completa las tareas sin ayuda y qué dificultades encuentra.

## 5. Cuestionario de evaluación

Después de realizar las tareas, cada participante responderá las siguientes preguntas.

**Escala de valoración:**

1 = Muy difícil o poco claro  
2 = Difícil  
3 = Aceptable  
4 = Fácil  
5 = Muy fácil o muy claro

| ID | Pregunta | Valoración |
|---|---|---|
| Q01 | ¿Te ha resultado fácil encontrar las funciones que necesitabas? | 1 a 5 |
| Q02 | ¿Los botones y menús son claros? | 1 a 5 |
| Q03 | ¿La información de los encargos se entiende correctamente? | 1 a 5 |
| Q04 | ¿Los formularios son fáciles de completar? | 1 a 5 |
| Q05 | ¿Los mensajes y estados de los encargos son comprensibles? | 1 a 5 |
| Q06 | ¿Consideras que la aplicación puede facilitar el trabajo diario? | 1 a 5 |

### Preguntas abiertas

1. ¿Qué parte de la aplicación te ha resultado más difícil de utilizar?
2. ¿Qué cambiarías o mejorarías?

## 7. Análisis de resultados

Una vez realizadas las evaluaciones, se revisarán las respuestas y las dificultades observadas.

Se prestará especial atención a las tareas que varios participantes no puedan completar sin ayuda y a las preguntas con puntuaciones bajas.

Las mejoras necesarias se registrarán como incidencias o propuestas de cambio, según corresponda.

Cuando se apliquen correcciones importantes, se comprobará de nuevo que la funcionalidad puede utilizarse correctamente.

## 8. Estado actual

El procedimiento, las tareas y el cuestionario están preparados, pero todavía no se han realizado evaluaciones reales.

Los resultados se incorporarán a este documento durante las siguientes fases del desarrollo.

Se utilizarán datos ficticios durante las pruebas para evitar publicar información de clientes reales.
