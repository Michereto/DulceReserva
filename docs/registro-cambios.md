# Registro de cambios - DulceReserva

Este documento se utilizará para registrar y controlar las modificaciones que puedan surgir durante el desarrollo de DulceReserva.

El objetivo es valorar los cambios antes de realizarlos, comprobar cómo afectan a la planificación y mantener actualizada la documentación del proyecto.

## 1. Procedimiento de gestión de cambios

Cuando se proponga una modificación, se seguirán estos pasos:

1. Identificar el cambio solicitado y explicar su motivo.
2. Comprobar qué funcionalidades, tareas o requisitos se verían afectados.
3. Valorar el tiempo adicional, los recursos necesarios y las posibles consecuencias para el calendario.
4. Decidir si el cambio se aprueba, se aplaza o se rechaza.
5. Registrar la decisión y su justificación.
6. Si se aprueba, actualizar las tareas de GitHub Projects y la documentación correspondiente.
7. Comprobar posteriormente que el cambio funciona correctamente.

## 4. Ejemplo de utilización (simulado)

**Identificador:** C-EJ01

**Fecha:** Ejemplo sin fecha real

**Responsable:** Responsable del proyecto

**Descripción del cambio:** Incorporar el envío de un correo electrónico cuando un encargo cambie al estado preparado.

**Motivo:** Facilitar la comunicación con el cliente y evitar llamadas innecesarias.

**Requisitos afectados:** Gestión de estados y notificaciones.

**Tareas afectadas:** Desarrollo de estados, integración y pruebas.

**Impacto en el tiempo:** Sería necesario añadir horas para configurar el envío de correos y comprobar su funcionamiento.

**Impacto en recursos o costes:** Podría requerirse un servicio de correo electrónico y su configuración.

**Impacto en el alcance:** Se añadiría una funcionalidad que no está incluida en la primera versión de DulceReserva.

**Decisión del ejemplo:** Aplazado para una posible versión futura.

**Justificación:** Se priorizan las funcionalidades principales de registro, consulta y gestión de encargos para cumplir la planificación inicial.

**Documentación afectada:** Requisitos y planificación, únicamente si el cambio llegara a aprobarse.

**Comprobación posterior:** No procede mientras el cambio esté aplazado.

Este caso es únicamente un ejemplo de cómo se utilizará el procedimiento. No corresponde a una solicitud real ni a una funcionalidad implementada.

## 5. Seguimiento y actualización

El registro se revisará cuando aparezcan propuestas de modificación y durante las revisiones periódicas del proyecto.

Los cambios aprobados se reflejarán en GitHub Projects y, cuando sea necesario, en los documentos de planificación, requisitos y pruebas.

El historial de GitHub permitirá consultar las actualizaciones realizadas en este archivo.
